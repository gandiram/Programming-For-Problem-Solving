The three control structures every program is built from

Structured programming proved that any program at all can be written using only these three: sequence (one statement after another — that was Unit I), selection (choose a path — Part A), and repetition (do it again — Part B). There is nothing else to learn about control flow.

Part A · Selection

Making Decisions

A selection statement tests a condition and chooses which statements to execute. C gives you two: if for any condition at all, and switch when one value is compared against a list of constants.

TOPIC 01Hanly & Koffman §4.3 · Forouzan & Gilberg Ch. 5

The if Statement

The if statement executes a statement only when a condition is true. If the condition is false, the statement is skipped entirely and the program carries on below.

1.1

Syntax and flow

if (condition) statement; /* runs only when the condition is true */

The condition must be in parentheses. It is any expression producing a value — remember from Unit I that C treats zero as false and any non-zero value as true.

1.2

Compound statements — one statement or many

An if controls exactly one statement. To control several, wrap them in braces to form a compound statement (also called a block).

Without braces — a classic bug

if (m >= 50)
    printf("Pass\\n");
    printf("Well done\\n");

Only the first printf is controlled. "Well done" prints even when you fail, because the indentation is a lie — the compiler ignores it.

With braces — correct

if (m >= 50) {
    printf("Pass\\n");
    printf("Well done\\n");
}

Both lines are inside the block, so both are controlled by the condition.

Habit worth forming now

Use braces every time, even for a single statement. It costs two characters and removes an entire category of bug — including the one where you later add a line and forget the braces were missing.

1.3

The semicolon trap

if (x > 0);  — the stray semicolon

if (n > 0);
    printf("positive");

The semicolon is an empty statement, and that empty statement becomes the body of the if. The printf is then outside the if and runs always. The compiler usually gives no error at all. Never put a semicolon straight after if (...).

Where if chooses whether to act, if-else chooses between two alternatives. Exactly one of the two branches runs — never both, never neither.

TOPIC 03Hanly & Koffman §4.6–4.7

  
Nested if and the else-if Ladder

  
An if whose branch contains another if is nested. When the nesting always happens in the else part, we write it as a flat else-if ladder — the standard way to choose among several ranges.


  

    
3.1
The else-if ladder

    
if (marks >= 90)       grade = 'A';
else if (marks >= 75)  grade = 'B';
else if (marks >= 50)  grade = 'C';
else                  grade = 'F';

    

      Why order matters so much
      
Conditions are tested top to bottom, and testing stops at the first true one. So the ladder must run from the most restrictive to the least. If you wrote marks >= 50 first, a student with 95 would match it and be graded C — every mark above 50 would collapse into one grade.

      
Because the tests are ordered, you never need to write marks >= 75 && marks < 90. Reaching the second test already proves the first was false.

    

  


  

    
3.2
The dangling else

    

      Which if does an else belong to?
      
if (a > 0)
    if (b > 0) printf("both");
else printf("a not positive");

      
The indentation suggests the else belongs to the outer if. It does not. An else always binds to the nearest unmatched if — the inner one. So with a = 5, b = -2 this prints "a not positive", which is plainly wrong.

      
The fix is braces: if (a > 0) { if (b > 0) printf("both"); } else printf("a not positive");

    

  







  
TOPIC 04Hanly & Koffman §4.8

  
The switch Statement

  
The switch statement selects one of many blocks by comparing a single value against a list of constants. It is often clearer than a long else-if ladder — but only when you are testing one value for equality.


  

    
4.1
Syntax

    
switch (expression) {
    case constant1:
        statements;
        break;
    case constant2:
        statements;
        break;
    default:
        statements;
}

    

    

      
PartRule

      
        
expressionMust produce an integer type — int or char. Never float, double or a string.

        
case labelsMust be constants, not variables and not ranges. case x: and case 1..5: are both illegal in C.

        
breakEnds the switch. Without it execution falls through into the next case.

        
defaultRuns when no case matches. Optional, but including one is good practice.

      
    

    

  


  

    
4.2
Fall-through — the behaviour that surprises everyone

    
A case label is an entry point, not a self-contained block. Once execution jumps in, it keeps going through the following cases until it meets a break or the closing brace.

    

      
Forgotten break

        
switch (2) {
 case 1: printf("one ");
 case 2: printf("two ");
 case 3: printf("three ");
    break;
}

        
Prints two three — it enters at case 2 and keeps falling until the break.

      
Deliberate fall-through

        
switch (ch) {
 case 'a':
 case 'e':
 case 'i':
 case 'o':
 case 'u':
    printf("vowel");
    break;
}

        
Empty cases stacked together are the standard way of saying "any of these".

    


    

      
Trace — a switch with a missing break

      
Watch execution enter at case 2 and keep going.

4.3
switch versus else-if ladder

    

    

      
Pointswitchelse-if ladder

      
        
TestsOne expression against constants, equality onlyAny conditions at all, each independent

        
Data typeint or char onlyAny type, including float and double

        
RangesCannot test a rangeHandles ranges naturally

      Quick rule
      
Choosing from a menu of fixed values → switch. Choosing by a range or a compound condition → else-if ladder.

    

  





  
Part B · Repetition

  
Loops — Doing It Again

  
A loop repeats a block of statements while a condition stays true. C offers three, and they differ in only one respect: where the test happens. Get that straight and all three become obvious.

  

    Topic 05The while Loop
    Topic 06The for Loop
    Topic 07The do-while Loop
    Topic 08Nested Loops
  






  Every loop needs the same three things
  
1. Initialisation — set the control variable before the loop starts. 2. Condition — the test that keeps the loop going. 3. Update — change the control variable so the condition eventually becomes false. Miss any one of the three and you have an infinite loop.







  
TOPIC 05Hanly & Koffman §5.2–5.4

  
The while Loop

  
The while loop tests before each pass. It is an entry-controlled loop, which means that if the condition is false at the start, the body never runs at all — not even once.


  

    
5.1
Syntax and flow

    
initialisation;
while (condition) {
    body;
    update;
}

    

      
    

  


  

    
5.2
Trace it — sum of the first n numbers

    
Step through and watch i climb while sum accumulates. The condition is tested before every pass, including the very first.


    

      
Tracing sum.c with n = 5

      
Expected result: 1 + 2 + 3 + 4 + 5 = 15.

      

        

          
sum.cexecuting

Addresses shown in decimal, as &variable would print. They change every run.

      The two ways a while loop goes wrong
      
Forgetting the update. while (i <= n) sum += i; — i never changes, so the condition stays true forever and the program hangs.

      
A semicolon after the condition. while (i <= n); gives the loop an empty body, so it spins forever doing nothing at all.

    

  


  

    
5.3
Sentinel-controlled loops

    
When you do not know in advance how many values there are, use a sentinel — an agreed value that means "stop". The read happens once before the loop and again at the end of the body.

    
READ  value
while (value != -1) {      /* -1 is the sentinel */
    process value
    READ value
}

    

      Choose a sentinel that cannot be real data
      
For exam marks, -1 is safe because no mark is negative. For temperatures, -1 would be a disaster — you would stop at a genuine reading. Pick a value outside the possible range of the data.

    

  







  
TOPIC 06Hanly & Koffman §5.5

  
The for Loop

  
The for loop is the counting loop. It does exactly what a while loop does, but it gathers the initialisation, the condition and the update into one line, where you cannot forget any of them.


  

    
6.1
Syntax — three parts, two semicolons

    
for (initialisation ; condition ; update) {
    body;
}

    

      
    

    

      The order never changes
      
Initialise once, then test → body → update repeatedly. Note that the update runs after the body, not before — so on the first pass the body sees the initial value.

    

  


  

    
6.2
Trace it — factorial

    

      
Tracing factorial.c with n = 5

      
Watch fact multiply up while i counts. Expected: 5! = 120.

      

        

          
factorial.cexecuting

          

        

          
Memory — name, value, address

            
Addresses shown in decimal, as &variable would print. They change every run.

          
Screen output

        

      

      
InstructionPress Step to begin.

      

        
        
        
        
        
      

    

  


  

    
6.3
Variations you are allowed to write

    

    

      
Written asMeaning

      
        
for (i = 10; i >= 1; i--)Counts down instead of up

        
for (i = 0; i <= 20; i += 5)Steps by 5: 0, 5, 10, 15, 20

        
for (i = 1, j = 10; i < j; i++, j--)Two control variables, using the comma operator

        
for ( ; i < n; i++)Initialisation omitted — i was set earlier

        
for ( ; ; )All three omitted — an infinite loop, exited with break

      
    

    

    

      for (i = 1; i <= 5; i++);  — the stray semicolon again
      
The loop body becomes the empty statement, so the loop runs five times doing nothing, and the block below runs once with i already at 6. This mistake produces no compiler error, only a wrong answer.

    

  


  

    
6.4
while or for — which should you use?

    

      
Use for when
You know how many times the loop should run, or you are counting through a range. "Print the table of 7" and "sum the first n numbers" are for-loop problems.

      
Use while when
Repetition depends on a condition rather than a count — reading until a sentinel, or halving a number until it reaches zero. You cannot say in advance how many passes there will be.

    

    
Both are equally powerful: any for loop can be rewritten as a while loop and the other way round. The choice is about which one states your intention more clearly.

  







  
TOPIC 07Hanly & Koffman §5.10

  
The do-while Loop

  
The do-while loop tests after each pass. It is an exit-controlled loop, and that single difference has one important consequence: the body always runs at least once, whatever the condition says.


  

    
7.1
Syntax and flow

    
do {
    body;
    update;
} while (condition);      /* note the semicolon */

    

      
    

    

      Two things students forget
      
The semicolon after while (condition) is required — this is the one place where a semicolon follows a while, and leaving it out is a syntax error.

      
The body runs before the first test. With int i = 100; do { printf("%d", i); } while (i < 10); the value 100 is printed even though the condition was false from the start.

    

  


  

    
7.2
Where do-while is genuinely the right choice

    
Any task that must happen once before you can decide whether to repeat it: showing a menu, asking for input, or peeling digits off a number.

    

      
Menu-driven programs

        
You must display the menu and read the choice before you can know whether the user picked "exit".

      
Counting digits

        
The number 0 has one digit. A while (n != 0) loop would report zero digits for it; a do-while correctly reports one.

    

    

    

      
Pointwhiledo-while

      
        
Test positionBefore the bodyAfter the body

        
Control typeEntry-controlledExit-controlled

        
Minimum passes01

        
Semicolon at the endNoYes, after while(...)

        
Typical useMay not need to run at allMust run at least once

      
    

    

  







  
TOPIC 08Hanly & Koffman §5.9

  
Nested Loops

  
A loop inside another loop is a nested loop. The rule that governs everything: the inner loop completes all of its passes for every single pass of the outer loop.


  

    
8.1
How the counts multiply

    

      
pattern.cnested for

      
1for (i = 1; i <= 3; i++) {      /* outer: runs 3 times      */2    for (j = 1; j <= i; j++)      /* inner: runs i times each  */3        printf("*");4    printf("\n");              /* end of the row            */5}

    

    

    

      
Outer pass (i)Inner loop runsRow printed

      
        
i = 1j = 1  (1 time)*

        
i = 2j = 1, 2  (2 times)**

        
i = 3j = 1, 2, 3  (3 times)***

      
    

    

    

      Counting total passes
      
If the outer loop runs m times and the inner runs n times per outer pass, the inner body executes m × n times. Two nested loops of 1000 iterations each mean a million passes — which is why nesting is where slow programs come from.

    

    

      Reusing the same control variable
      
Using i for both loops makes the inner loop destroy the outer loop's counter, usually producing an infinite loop. Inner loops conventionally use j, then k.

      
Also remember to re-initialise the inner counter. In a for loop that happens automatically; in a nested while loop you must write j = 1; inside the outer body, or the inner loop runs only on the first pass.

TOPIC 09Hanly & Koffman §5.11 · Forouzan & Gilberg Ch. 6

  
The break Statement

  
break leaves the loop or switch it sits in, immediately. Execution resumes at the first statement after that loop — the condition is not tested again and the update is not run.


  

    
9.1
Its two jobs

    

      
Inside a switch

        
Ends the switch so control does not fall through into the next case. This is required for the switch to behave the way most people expect.

      
Inside a loop

        
Abandons the loop early because the work is done or something has gone wrong — searching, validating, or stopping on a sentinel.

    

    

      
prime.cbreak ends the search early

      
1isPrime = 1;2for (i = 2; i < n; i++) {3    if (n % i == 0) {       /* found a divisor        */4        isPrime = 0;5        break;              /* no point testing more  */6    }7}

    

    
Once a single divisor is found the answer is settled, so continuing to test the remaining values would waste time. For n = 1000, break turns 998 tests into one.

    

      break only escapes ONE level
      
In nested loops, break leaves the inner loop only — the outer loop carries on. To leave both you need a flag variable tested in the outer condition, or a goto (one of its few defensible uses).

    

  







  
TOPIC 10Hanly & Koffman §5.11

  
The continue Statement

  
continue skips the rest of the current pass and goes straight to the next one. Unlike break, the loop is not abandoned — only this one iteration is cut short.


  

    
10.1
break versus continue

    

      
    

    

    

      
Pointbreakcontinue

      
        
EffectLeaves the loop completelySkips to the next iteration

        
Remaining iterationsAbandonedStill happen

        
In a for loop, the updateNot executedIs executed

        
Works in switchYes — its main jobNo, only in loops

      
    

    

    

      continue in a while loop can hang the program
      
while (i <= 10) { if (i % 2) continue; sum += i; i++; }

      
When i is odd, continue jumps back to the test without ever reaching i++, so i stays odd forever. In a for loop this cannot happen, because the update is part of the loop header and always runs.

    

  







  
TOPIC 11Forouzan & Gilberg Ch. 6 · Kernighan & Ritchie §3.8

  
The goto Statement

  
goto transfers control to a labelled statement elsewhere in the same function. It is the most powerful jump and the least welcome one.


  

    
11.1
Syntax

    
    goto label;
    ...
label:                      /* a label is a name followed by a colon */
    statement;

    

      
goto_demo.ca loop built with goto

      
1i = 1;2start:                          /* the label */3    printf("%d ", i);4    i++;5    if (i <= 5) goto start;    /* jump back up */

    

    
That prints 1 2 3 4 5 — exactly what for (i = 1; i <= 5; i++) does in one line, with the control logic gathered in one place instead of scattered across three.

  


  

    
11.2
Why goto is avoided

    

      
The case against

        
    
          
  • Control can arrive at a label from anywhere, so you cannot tell what the program state is by reading nearby code
    • 
          
  • It produces "spaghetti code" — flow that crosses over itself and cannot be followed on paper
    • 
          
  • It makes testing and debugging far harder
    • 
          
  • Anything goto can do, the three structured constructs can do — this was proved formally
    • 
        

      
The one accepted use

        
Breaking out of deeply nested loops in a single jump, where the alternative is several flag variables that obscure the logic:

        
for (...)
  for (...)
    if (found) goto done;
done:

    

    

      Two hard restrictions
      
A goto can only jump within the same function, and the label must exist in that function. You cannot jump into the middle of another function, and you cannot jump into a block from outside it.

    

    

      For your exam
      
Know the syntax, be able to trace a goto-based loop, and be able to state why structured constructs are preferred. Then write your own programs with for, while and break.

Summary and Common Programming Errors


  

    
S.1
The errors that cost most marks

    

      
Errors the compiler will NOT catch

        
    
          
  • if (x = 5) — assignment instead of comparison, so the test is always true
    • 
          
  • if (x > 0); — stray semicolon makes an empty body
    • 
          
  • for (i=1; i<=n; i++); — same trap, loop body does nothing
    • 
          
  • Missing braces, so only the first statement is controlled
    • 
          
  • Missing break in a switch, causing fall-through
    • 
          
  • Missing update, giving an infinite loop
    • 
          
  • continue in a while loop, jumping over the update
    • 
        

      
Errors the compiler WILL catch

        
    
          
  • Missing semicolon after while (cond) in a do-while
    • 
          
  • switch on a float or double
    • 
          
  • A variable or a range used as a case label
    • 
          
  • Two identical case constants in one switch
    • 
          
  • else with no matching if
    • 
          
  • break or continue outside a loop
    • 
          
  • A goto to a label that does not exist
    • 
        

    

    

      The off-by-one check
      
Before you submit a loop, ask two questions: does it run one time too many, or one too few? i < n gives n−1 passes from 1; i <= n gives n. Trace the first and last passes by hand — that catches almost every off-by-one error.

    

  


  

    
S.2
One line per topic

    

      
01ifRuns a statement only when the condition is true. Controls exactly one statement — use braces for more.

      
02if-elseChooses between two alternatives; exactly one branch runs. == compares, = assigns.

      
03Nested if / ladderTested top to bottom, stopping at the first true condition — so order from most restrictive down. An else binds to the nearest unmatched if.

      
04switchOne int or char value against constant case labels. Without break, execution falls through into the following cases.

      
05whileEntry-controlled: tests before the body, so it may run zero times. Needs initialisation, condition and update.

      
06forA while loop with all three parts in the header. Order: initialise once, then test → body → update.

      
07do-whileExit-controlled: tests after the body, so it always runs at least once. Needs a semicolon after while(...).

      
08Nested loopsThe inner loop completes fully for every outer pass. Total passes = outer × inner. Use different counters.

      
09breakLeaves the loop or switch immediately — the update is not run. Escapes one level of nesting only.

      
10continueSkips the rest of the current pass and goes to the next. In a for loop the update still runs; in a while loop it does not.

      
11gotoJumps to a label in the same function. Anything it does can be done with the structured constructs, so it is avoided.

      
12ChoosingRanges → else-if ladder. Fixed values → switch. Known count → for. Condition-driven → while. Must run once → do-while.
