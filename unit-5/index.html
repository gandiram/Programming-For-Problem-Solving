Two operators run the whole unit

&x means "the address of x". *p means "the value stored at the address in p". They are exact opposites, so *&x is simply x. Every topic here is an application of those two symbols.

Pointers and Addresses

Memory is a long row of numbered bytes. Every variable occupies some of them, and the number of its first byte is its address. A pointer is a variable whose value is such an address.

Pointer Types and Declaration

  
A pointer is declared with a type and a star. The type is not decoration: it tells the compiler how many bytes to read when you dereference, and how far to move when you add 1.


  

    
2.1
Declaring pointers

    
int    *p;      /* p points at an int    */
float  *q;      /* q points at a float  */
char   *s;      /* s points at a char   */
double *d;      /* d points at a double */

    

    

      
DeclarationPoints at*p readsp + 1 moves

      
        
char *sa char1 byte1 byte

        
int *pan int4 bytes4 bytes

        
float *qa float4 bytes4 bytes

        
double *da double8 bytes8 bytes

      
    

    

    

      Every pointer is the same size, whatever it points at
      
An address is an address, so sizeof(int*) and sizeof(double*) are equal — typically 8 bytes on a 64-bit machine. The type does not change the pointer's size; it changes what happens when you use the pointer.

    

    

      Three declaration traps
      
1. int *p, q; declares one pointer and one ordinary int. The star belongs to the name, not the type. Write int *p, *q; for two pointers.

      
2. An uninitialised pointer holds a garbage address. Dereferencing it usually crashes the program. Set it to NULL if you have nothing for it yet.

      
3. int *p = &x; initialises p, not *p. It does not mean "the value at p is &x".

    

  


  

    
2.2
NULL — a pointer that deliberately points nowhere

    
NULL is the address 0, guaranteed never to be a valid variable. It is how a function reports "no result", and how you mark a pointer as unset.

    

      
nullcheck.calways test before dereferencing

      
1int *p = 0;              /* NULL: points nowhere */23if (p != 0)               /* check FIRST */4    printf("%d", *p);5else6    printf("pointer is not set\n");

    

  







  
TOPIC 03Kernighan & Ritchie §5.2 · Hanly & Koffman §6.5

  
Pointers and Function Arguments

  
This is the payoff. In Unit III a function could not change its caller's variable, because arguments are copied. Give the function an address and it can.


  

    
3.1
The swap that finally works

    

      
Unit III — fails

        
void swap(int a, int b)
{ int t=a; a=b; b=t; }

swap(x, y);

        
a and b are copies. They swap; x and y never move.

      
Unit V — works

        
void swap(int *a, int *b)
{ int t=*a; *a=*b; *b=t; }

swap(&x, &y);

        
a and b are addresses. Writing through them reaches x and y themselves.

    

    

      Call by value, always
      
C is still passing by value here — it copies the address. But a copy of an address points at the same place as the original, so the function can reach the caller's data. This is often called "call by reference", though strictly C only ever copies.

      Returning more than one value
      
A function can return only one value — but it can be given several addresses and write through all of them. void minMax(int a[], int n, int *mn, int *mx) delivers two results at once. That is the standard C solution.

Pointers and Arrays

  
In C, arrays and pointers are almost the same thing. The name of an array is the address of its first element, and that fact explains everything about arrays you met in Unit IV.


  

    
4.1
The equivalence

    

      
    

    

      How the compiler reads a[i]
      
The compiler translates a[i] into *(a + i) every time. Subscript notation is a convenience; pointer arithmetic is what actually happens. It also means a[2] and 2[a] are both legal and identical — a curiosity that shows the mechanism, not something to write.

    

  


  

    
4.2
Where arrays and pointers differ

    

    

      
PointArray aPointer p

      
        
Memory reservedThe whole block of elementsOnly enough for one address

        
Can it be reassigned?No — a = p; is an errorYes — p = a; then p++

        
sizeofThe whole array, e.g. 20 bytesThe size of one address

        
Created byA declarationA declaration, or malloc

      
    

    

    

      The one that catches everyone
      
An array name is a constant address. a++ is an error, but p++ is fine. That is why you copy the array name into a pointer before walking through it with p++.

Address Arithmetic

  
Adding 1 to a pointer does not add 1 to the address. It moves to the next element — so the address advances by the size of whatever the pointer points at. This is the single most important idea in the topic.


  

    
5.1
p + 1 means "the next element"

    

      
    

    

    

      
OperationAllowed?Meaning

      
        
p + n , p - nYesMove n elements forward or back

        
p++ , p--YesMove to the next or previous element

        
q - pYesHow many elements apart they are

        
p == q , p < qYesCompare positions in the same array

        
p + qNoAdding two addresses is meaningless

        
p * 2 , p / 2NoMultiplying an address is meaningless

      
    

    

    

      
walk.cthe pointer idiom

      
1int a[5] = {1,2,3,4,5};2int *p;34for (p = a; p < a + 5; p++)   /* walk with the pointer itself */5    printf("%d ", *p);

    

    

      Walking off the end
      
a + 5 is a legal address to compare against — C guarantees one position past the end exists for exactly this purpose. But *(a + 5) must never be read. Use it as a limit, never as a value.

Array of Pointers

  
An array of pointers holds several addresses. Its classic use is a list of strings, where each entry can be a different length — something a rectangular 2D array cannot manage without waste.


  

    
6.1
Declaration and use

    
char *names[3];        /* an array of 3 char pointers */

names[0] = "Amit";
names[1] = "Bina";
names[2] = "Chandrasekhar";

    

      
    

    

    

      
Pointchar *names[3]char names[3][20]

      
        
What it stores3 addresses60 characters

        
String lengthsEach can differAll limited to 19 + terminator

        
MemoryExactly what each string needsFixed, and wasted on short names

        
Can an entry be changed?Point it somewhere else, cheaplyCopy the characters with strcpy

        
Entries modifiable in place?Not if they are string literalsYes

      
    

    

    

      String literals are read-only
      
char *s = "hello"; s[0] = 'H'; compiles but crashes on most systems, because a string literal lives in read-only memory. If you need to modify the text, put it in an array: char s[] = "hello"; — that copies the characters into memory you own.

    

  







  
TOPIC 07Kernighan & Ritchie §5.6 · Forouzan & Gilberg Ch. 9

  
Pointers to Pointers

  
A pointer is a variable, so it too has an address — and something can point at it. That is a pointer to a pointer, declared with two stars.


  

    
7.1
Three levels

    

      
    

    

      
double.ctwo stars

      
1int x = 25;2int *p = &x;        /* p points at x  */3int **pp = &p;      /* pp points at p */45**pp = 99;          /* changes x itself */

    

    

      Why it exists
      
The commonest real use: a function that must change the caller's pointer, not just what it points at. To make allocate(&p) set p itself, the function needs int ** — the same reasoning as passing &x to change an int. It is also how char *argv[] works in main.

    

    

      Count the stars carefully
      
Each * in the declaration is one level of indirection, and each * in use removes one. With int **pp: pp is an address, *pp is a pointer, **pp is the int. Using one star too few assigns to the wrong thing.

    

  







  
TOPIC 08Kernighan & Ritchie §5.7, §5.11

  
Pointer to Function, and Pointers with 2D Arrays


  

    
8.1
Pointer to a function

    
A function occupies memory too, so it has an address — and a pointer can hold it. This lets you pass behaviour to a function, not just data.

    
int (*fp)(int, int);      /* fp points at a function taking two ints, returning int */

fp = add;                  /* the function name is its address */
result = fp(3, 4);        /* call through the pointer */

    

      The brackets are not optional
      
int (*fp)(int, int); is a pointer to a function returning int.

      int *fp(int, int); is a function returning a pointer to int.

      One pair of brackets changes the meaning completely. Read the declaration from the name outwards: fp is a pointer, to a function, taking two ints, returning int.

    

    

      Where you meet it
      
The standard library's qsort takes a function pointer so you can decide how two items compare. Menu tables, callbacks and event handlers all use the same idea: store the function to call, rather than writing a switch.

    

  


  

    
8.2
Pointers and multidimensional arrays

    
A 2D array is stored as one continuous block in row-major order, so a single pointer can walk the whole thing — the row and column are just arithmetic.

    

      
flat.cone pointer, whole matrix

      
1int m[2][3] = {{1,2,3},{4,5,6}};2int *p = &m[0][0];        /* address of the first element */34for (i = 0; i < 6; i++)      /* 2 x 3 = 6 elements in a row */5    printf("%d ", *(p + i));   /* prints 1 2 3 4 5 6 */

    

    

      The offset formula, again
      
m[i][j] is *(p + i * columns + j). This is the same i × cols + j you met in Unit IV — and now you can see it is literally pointer arithmetic. It is also why a function parameter must state the column count: without it the compiler cannot compute the offset.

Dynamic Memory Allocation

  
int a[100]; fixes the size when you write the program. Dynamic allocation lets you decide when you run it — ask the user for n, then request exactly n elements.


  

    
9.1
The four functions

malloc(bytes)Requests one block of the given sizeGarbage

dynamic.cthe standard shape

      
1#include <stdlib.h>          /* required for malloc and free */23int n, *p;4scanf("%d", &n);            /* the size is known only NOW */56p = (int *) malloc(n * sizeof(int));78if (p == 0) {                /* ALWAYS check -- it can fail */9    printf("out of memory\n");10    return 1;11}1213... use p[0] to p[n-1] exactly like an array ...1415free(p);                    /* give it back when finished */

    

    

      Reading line 6
      
n * sizeof(int) computes the bytes needed — never assume 4. malloc returns a general address, so the cast (int *) tells the compiler what it points at. Once assigned, p is used exactly like an array: p[i] works normally.

      The three classic memory bugs
      
1. Memory leak. Allocating and never freeing. The program's memory use grows until it is killed. Every malloc needs exactly one free.

      
2. Dangling pointer. Using a pointer after free(p). The memory now belongs to something else. Set p = NULL; straight after freeing.

      
3. Double free. Calling free(p) twice corrupts the allocator and usually crashes later, far from the real cause.

      
The runner on this page detects all three and tells you which one happened. A real compiler will not.

String Basics

  
C has no string type. A string is a char array ending with the null character '\0' — the value zero. Every string function in C works by hunting for that terminator.


  

    
10.1
The terminator is the whole design

    

      
    

    

    

      
Written asMeaning

      
        
char s[10] = "HELLO";10 cells; the text is copied in, terminator added

        
char s[] = "HELLO";The compiler counts: 6 cells, not 5

        
char *s = "HELLO";A pointer to a read-only literal

        
char s[6] = {'H','E','L','L','O','\0'};The same thing written out longhand

      
    

    

    

      Always leave room for the terminator
      
char s[5] = "HELLO"; has no space for the '\0'. Functions like printf("%s") then run past the end, printing rubbish until they happen to meet a zero byte. An n-character string needs an array of n+1.

    

  


  

    
10.2
Reading and writing strings

    

    

      
Written asDoesWatch out

      
        
printf("%s", s)Prints up to the terminatorNo & — the array name is already an address

        
scanf("%s", s)Reads one wordStops at the first space; no & needed

        
puts(s)Prints the string and a newlineSimple, adds \n for you

        
fgets(s, n, stdin)Reads a whole line safelyKeeps the newline; limited to n−1 chars

        
gets(s)Reads a whole lineNever use it — no length limit, removed from C11

      
    

    

    

      Whole-line input
      
scanf("%s", name) on "Ravi Kumar" stores only "Ravi". For a full line use fgets(name, 50, stdin), which is also safe: it will never write more than 50 characters, whatever the user types. That is exactly the flaw that made gets a security disaster.

String Library Functions

  
The header <string.h> supplies the operations you cannot do with = and ==. Every one of them relies on the '\0' being there.


  

    
11.1
The functions in the syllabus

    

    

      
FunctionDoesReturns

      
        
strlen(s)Counts characters before the '\0'The length

        
strcpy(d, s)Assignment: copies s into dd

        
strncpy(d, s, n)Copies at most n charactersd

        
strcat(d, s)Concatenation: appends s to dd

        
strncat(d, s, n)Appends at most n charactersd

        
strcmp(a, b)Comparison, alphabetical<0, 0, or >0

        
strncmp(a, b, n)Compares the first n characters<0, 0, or >0

      
    

    

    

      Why = and == do not work on strings
      
s1 = s2; is an error — an array name is a constant address and cannot be reassigned. Use strcpy.

      
if (s1 == s2) compiles but compares addresses, so it is almost always false even when the text matches. Use if (strcmp(s1, s2) == 0).

    

    

      Reading strcmp's result
      
It returns the difference, not a yes or no. Negative means the first comes earlier alphabetically, zero means equal, positive means later. So strcmp("apple", "banana") is negative. The zero-means-equal convention catches everybody once — if (strcmp(a,b)) is true when they differ.

    

  


  

    
11.2
Substrings, and the danger in strcat

    
A substring is extracted by copying a limited number of characters from a starting position, then adding the terminator yourself:

    

      
substring.cstrncpy

      
1char full[30] = "Programming", part[10];23strncpy(part, full + 3, 4);   /* 4 chars starting at index 3 */4part[4] = '\0';             /* strncpy may NOT add it -- you must */56printf("%s", part);         /* gram */

    

    

      strcat does not check the destination
      
char a[10] = "Hello, "; strcat(a, "World"); needs 13 cells but has 10. strcat writes past the end regardless — a buffer overflow, the single most exploited class of bug in C. Always size the destination for the combined length plus one.

    

  







  
TOPIC 12Kernighan & Ritchie §5.5 · Unit V synthesis

  
Character Pointers and Functions

  
Because a string is reached through an address, string functions take char * parameters. Writing them yourself is the best way to see how the library works — and it ties the whole unit together.


  

    
12.1
strlen, written twice

    

      
With a subscript

        
int mylen(char s[])
{
  int n = 0;
  while (s[n] != '\0') n++;
  return n;
}

        
Familiar from Unit IV, and easy to read.

      
With a pointer

        
int mylen(char *s)
{
  int n = 0;
  while (*s != '\0') { n++; s++; }
  return n;
}

        
Idiomatic C. s is a copy of the address, so moving it is harmless.

    

    

      Why the function may move s
      
The pointer is passed by value, so s++ moves the function's own copy. The caller's array — and the caller's own pointer — are untouched. Only writing through it with *s = ... would change the caller's data.

S.2
One line per topic

    

      
01Pointers & addressesEvery variable has an address; a pointer is a variable that holds one. & gives an address, * follows one, and they are exact opposites.

      
02Pointer typesThe type says what the pointer points at, which fixes how many bytes * reads and how far +1 moves. All pointers are the same size. NULL means "points nowhere".

      
03Function argumentsPassing an address lets a function change the caller's variable — the swap that failed in Unit III now works. Several addresses give several results.

      
04Pointers & arraysAn array name is the address of element 0, so a[i], *(a+i), p[i] and *(p+i) are identical. An array name cannot be reassigned; a pointer can.

      
05Address arithmeticp+n moves n elements. Subtracting two pointers gives the element count between them. Adding or multiplying pointers is meaningless.

      
06Array of pointersStores several addresses, typically one per string, so each string uses only the space it needs. String literals are read-only.

      
07Pointers to pointersA pointer has an address too. Each star is one level of indirection; **pp reaches the value. Needed to change a caller's pointer.

      
08Function pointers & 2Dint (*fp)(int,int) holds a function's address — the brackets matter. A 2D array is one block, so m[i][j] is *(p + i×cols + j).

      
09Dynamic allocationmalloc sizes memory at run time and returns garbage; calloc zeroes it; free returns it. Always check for NULL, and free exactly once.

      
10String basicsA string is a char array ending in '\0', so n characters need n+1 cells. strlen counts characters; sizeof reports the array.

      
11String librarystrcpy assigns, strcat joins, strcmp compares and returns <0, 0 or >0. = and == do not work on strings. strcat does not check the destination size.

      
12Character pointersString functions take char * and loop until the terminator. Moving the parameter is safe because the pointer itself was copied.
